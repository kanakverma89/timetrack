# Free-tier portfolio deployment (Vercel + Render + Neon)

**Status: prepared, not deployed.** The files and commands below were checked locally (the exact Render start
command, in production mode, against a throwaway database; the smoke tests against a local copy). Nothing has
been run on Vercel, Render or Neon yet, so the "first deployment gate" in section 6 is still to be passed.

This is a *portfolio demo* setup, not a production one. For a real deployment see `docs/operations.md`.

## 1. Architecture

```
Browser ──https──▶ Vercel  (static React build from frontend/dist, SPA fallback)
                     │  rewrite /api/*  → looks like the same origin to the browser
                     ▼
                   Render free web service  (Docker image backend/Dockerfile;
                     │                        `alembic upgrade head`, then uvicorn)
                     │  postgresql+psycopg://…?sslmode=require
                     ▼
                   Neon free Postgres (direct connection)

GitHub (main) ── auto-deploys ──▶ Vercel and Render      GitHub Actions ── smoke tests ──▶ the live URL
```

**Why the proxy:** the session cookie is `SameSite=Lax` and the API only accepts requests whose `Origin` is on an
allow-list. A page on `*.vercel.app` calling `*.onrender.com` directly would not carry the cookie, so Vercel
forwards `/api/*` to Render and the browser only ever talks to one origin. The app needed no code changes.

| Piece | Provider | Why |
| --- | --- | --- |
| Frontend | Vercel Hobby | free static hosting, external rewrites, deploys from a private GitHub repo |
| API | Render free web service | runs the existing Docker image unchanged |
| Database | Neon free | real PostgreSQL; Render's free Postgres **expires after 30 days** |

## 2. Free-tier limits (read from the providers' pages on 2026-10-25; they can change)

- **Render web (free):** 750 instance-hours a month (enough for one always-on service); **spins down after 15 minutes
  without traffic and takes about a minute to wake**; no persistent disk; no pre-deploy command (paid), so
  migrations run in the start command; outbound email ports blocked. Render says free instances are for hobby
  projects and testing, not production.
- **Neon (free):** 1 GB, 100 compute-hours a month, compute suspends after 5 minutes idle, a 6-hour restore window and
  one manual snapshot, no scheduled backups. Hitting a limit suspends compute or blocks writes; it does not bill.
- **Vercel Hobby:** free for **non-commercial personal use only** (a portfolio is fine; using it to sell services is
  not), 100 deployments a day.
- **Payment details:** not stated on the pages read. You will see at sign-up whether a card is requested; review
  any prompt yourself and stay on the free plans.

Expect the **first visit after a quiet spell to take about a minute**; later requests are fast.

## 4. Environment variables

| Variable | Where | Value / owner |
| --- | --- | --- |
| `APP_ENV` | Render | `production` (in `render.yaml`) |
| `SESSION_SECRET` | Render | generated by Render (`generateValue`), never seen by you or the repo |
| `DATABASE_URL` | Render dashboard only | from Neon: the **direct** (not "pooled") string, with the scheme changed to `postgresql+psycopg://` and `?sslmode=require` kept |
| `CORS_ORIGINS` | Render dashboard | exactly your Vercel production URL, e.g. `https://timetrack-demo.vercel.app` (no trailing slash) |
| `BUSINESS_TIMEZONE`, `WEEK_START_DAY`, `LOG_LEVEL` | Render | in `render.yaml` (`Asia/Kolkata`, `MONDAY`, `INFO`) |
| `VITE_API_BASE_URL` | not set | the default `/api/v1` is what makes the proxy work |
| `DEMO_URL` (variable), `DEMO_EMPLOYEE_PASSWORD` (secret) | GitHub → Settings → Secrets and variables → Actions | for the smoke tests |

Never commit any of the values above. The API refuses to start in production with a short secret, a placeholder
password or a non-`https://` origin, and says which.

## 5. Setup steps (you do these; each one is a dashboard action)

1. **Merge this branch into `main`** (Render's Blueprint deploys `main`).
2. **Neon:** sign in, create a project. Copy the *direct* connection string. Turn `postgresql://` into
   `postgresql+psycopg://` and keep `?sslmode=require`.
3. **Pick the Vercel project name first** (e.g. `timetrack-demo-<yourname>`) so you know the final URL
   `https://<name>.vercel.app` for `CORS_ORIGINS`.
4. **Render:** New → Blueprint → choose the repository (authorise access to the private repo). It proposes the
   service `timetrack-demo-api` on the **Free** plan. The region is fixed to **Ohio** in `render.yaml` (it cannot be changed after the service is created), so create
   your Neon project in AWS US East 2 (Ohio) as well; the form does not offer a region choice. Enter `DATABASE_URL` and `CORS_ORIGINS` when asked. Wait for the
   first deploy; the health check is `/api/v1/health/ready`.
5. **Check the API URL.** Render gives `https://timetrack-demo-api.onrender.com` unless that name is taken (then it
   adds a suffix). If yours differs, edit the `destination` in `frontend/vercel.json`, commit and push to `main`.
6. **Vercel:** Add New → Project → import the repository. Set **Root Directory** to `frontend`, framework **Vite**,
   Node **22.x**; keep the build command `npm run build` and output `dist`. Deploy. No environment variables are
   needed. Use the *production* URL only (preview URLs have other origins and will fail the CSRF check).
7. **First deployment gate (section 6).** Do not continue until it passes.
8. **Create the demo accounts from your laptop** (never from the public site):
   ```bash
   cd backend
   export DATABASE_URL='postgresql+psycopg://…direct Neon string…?sslmode=require'
   export APP_ENV=development                     # seed.py refuses "production"
   read -rs SEED_PASSWORD; export SEED_PASSWORD   # the demo password you will publish (12+ chars)
   .venv/bin/python scripts/seed.py --sample-entries
   read -rs ADMIN_PASSWORD; export ADMIN_PASSWORD # a long random PRIVATE password
   .venv/bin/python scripts/maintain.py create-admin you@example.com "Your Name"
   unset DATABASE_URL SEED_PASSWORD ADMIN_PASSWORD
   ```
   The seed gives *every* demo account, including `admin@example.test`, the shared demo password. So next sign in to
   the live site as **your private admin** (you must choose a new password at first sign-in), open **Admin → Users**
   and **untick Active on `admin@example.test`**. Only then publish the employee and manager logins.
9. **GitHub:** add the variable `DEMO_URL` (the Vercel URL) and the secret `DEMO_EMPLOYEE_PASSWORD`, then run
   **Actions → deploy-verify**.

## 6. First deployment gate (proves the one assumption the docs did not confirm)

Run these against the Vercel URL (`$URL`), reading the password from the environment so it is never typed into a
command history:

```bash
URL=https://<name>.vercel.app
time curl -s -i $URL/api/v1/health/ready | head -12           # may take ~1 min if Render is asleep
read -rs PW
curl -s -i -c jar -X POST $URL/api/v1/auth/login -H 'Content-Type: application/json' -H 'X-Requested-With: timetrack' \
  -d "{\"email\":\"employee@example.test\",\"password\":\"$PW\"}" | grep -i -E '^HTTP|set-cookie'
curl -s -b jar $URL/api/v1/auth/me                             # expect your user, not 401
```
Pass = the login response carries a `Set-Cookie` that the next request sends back (so `/auth/me` returns the user),
the cold-start request succeeds rather than timing out, and a sign-in through the page in a browser works.
**If any of this fails, stop:** the fallback (the API serving the built frontend from Render) needs backend changes
and should be planned separately.

## 8. Known limitations and risks

- **Cold starts** (about a minute) and a demo that can be suspended if a free limit is exhausted.
- **Provider terms:** Render's free tier is for hobby/testing use; Vercel Hobby is non-commercial. Fine for a portfolio.
- **Shared demo password:** anyone can use the published employee and manager logins and can add/submit data. Reset
  by recreating the Neon database (or branch), then step 8 again.
- **Login throttle:** in memory and single instance. The API trusts forwarded headers (as in the Docker image) and
  Render's origin URL is public, so a caller could forge their address and sidestep the per-address throttle
  (`docs/security-review.md`, R-6). Mitigation: the private admin password must be long and random.
- **No scheduled backups** on Neon free (6-hour restore window, one manual snapshot). Take a `pg_dump` from your
  laptop with the commands in `docs/operations.md`, using the direct connection string.
- **No email:** notifications are logged only.
- **Preview deployments** on Vercel do not work for sign-in (different origin).
- The Vercel external rewrite's behaviour with `Set-Cookie` and with a slow (waking) origin is **not documented in the
  pages I read**; section 6 exists to prove it.

## 9. Rollback and recovery

- **Frontend:** Vercel → Deployments → promote a previous deployment.
- **API:** Render → Deploys → roll back to a previous deploy. Migrations are forward-only: roll back the code only if
  the older code still works with the current schema; otherwise restore data.
- **Data:** Neon instant restore (6 hours), the manual snapshot, or your own `pg_dump`.
- **Start over:** recreate the Neon database, redeploy the API (it migrates on start), run step 8.

## 10. Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| First page load hangs ~1 minute | Render woke from sleep; wait, then it is fast |
| API deploy fails: "Invalid production configuration" | `CORS_ORIGINS` not `https://…`, or `DATABASE_URL` still a placeholder; the log names which |
| `ModuleNotFoundError: psycopg2` or "could not translate" | `DATABASE_URL` is missing `+psycopg` after `postgresql` |
| Sign-in returns 403 | `CORS_ORIGINS` does not exactly match the URL in the address bar (scheme, host, no trailing slash) |
| Sign-in works but you are logged out on the next page | the proxy did not carry the cookie: section 6 failed |
| 404 on `/api/...` from Vercel | the `destination` host in `frontend/vercel.json` is not your Render URL |
| 502/504 right after idle | cold start; retry after a minute |
| Database errors after a quiet period | Neon was suspended; the first query wakes it, retry |
